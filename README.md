## О проекте

Цель репозитория — продемонстрировать навыки **анализа требований, планирования тестирования, разработки тестовых сценариев, документирования дефектов и оценки покрытия** на примере пользовательских сценариев e-commerce.

**Система под тестированием (SUT):** [American Eagle](https://www.ae.com/us/en) — действующий интернет-магазин. Это **личный учебный QA-проект**, не связанный с American Eagle и не являющийся официальным тестированием компании.

Документация составляется на основе анализа доступного поведения сайта и существующих авторских проектов по автоматизации. Поскольку официальная спецификация продукта отсутствует, предполагаемые требования будут явно отмечены как **допущения**, а не представлены как подтверждённые бизнес-требования.

> **Принцип достоверности:** сценарии в документации — это проектируемые проверки, пока они не выполнены и не получили фактический результат. Баг-репорты будут различать проверенные наблюдения, возможные дефекты, требующие уточнения требований, и демонстрационные учебные примеры.

## Цели

- Определить область и стратегию тестирования.
- Выделить позитивные, негативные и граничные сценарии.
- Применить техники тест-дизайна: **классы эквивалентности (EP)**, **анализ граничных значений (BVA)**, **таблицы решений** и **переходы состояний**.
- Подготовить чек-листы, тест-кейсы и трассировку «требование → проверка → результат → дефект».
- Продемонстрировать оформление воспроизводимых баг-репортов с доказательствами и оценкой Severity/Priority.
- Обосновать приоритеты для последующей автоматизации.

## Область тестирования

| Область | Примеры проверок | Приоритет |
|---|---|---|
| Навигация и главная страница | Header, категории, переходы | Medium |
| Поиск | Релевантные и нерелевантные запросы, пустой ввод | High |
| Каталог | Переходы, сортировка, фильтрация | High |
| Карточка товара | Размер, цена, доступность, добавление в корзину | High |
| Корзина | Количество, удаление, subtotal, несколько товаров | Critical |
| Аккаунт | Валидация форм регистрации и входа | Medium |
| REST API (дополнительно) | Guest token, Browse, Inventory, Bag | Medium |

Значения приоритетов — **оценка в рамках учебного тест-плана**, а не подтверждённые приоритеты бизнеса American Eagle.

## Правила оформления результатов

- `Not Run` — тест ещё не выполнялся.
- `Passed` — фактическое поведение соответствует ожидаемому при зафиксированных условиях.
- `Failed` — наблюдается расхождение, которое подлежит анализу.
- `Blocked` — выполнение невозможно из-за окружения, защиты сайта или недоступных данных.
- `Needs Clarification` — ожидаемое поведение не подтверждено требованиями.

Для каждого запуска по возможности фиксируются **дата, окружение, регион, браузер, шаги, тестовые данные и доказательства**. Наличие ошибки автоматизированного теста не доказывает наличие продуктового дефекта.

## Ограничения и этические принципы

- Тестируемый сайт — **production**, а не выделенный тестовый стенд.
- Поведение может различаться по региону, наличию VPN, состоянию сессии и anti-bot-защите.
- Не выполняются массовые запросы, обход защитных механизмов, реальные покупки или действия, создающие нежелательную нагрузку.
- Не публикуются токены, учётные данные, персональная информация и cookies.
- Функции, требующие реальных покупок или недоступных тестовых аккаунтов, остаются вне фактического выполнения.
