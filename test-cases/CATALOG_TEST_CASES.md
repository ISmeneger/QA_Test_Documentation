## Общие правила выполнения

- Перед прогоном зафиксировать дату/время и часовой пояс, ОС, браузер/версию, регион и локаль, VPN, URL, тип сессии и всплывающие окна.
- Использовать только публичный UI и обычные действия пользователя. Не обходить anti-bot, не выполнять массовые запросы и не публиковать cookies или токены.
- Для тестов подбирать доступные на момент запуска товары/категории. Если входное условие не выполняется, фиксировать `Blocked`/`Not Applicable` с пояснением, а не выдумывать результат.
- `Actual Result`, `Execution ID` и `Evidence` заполнять **только после выполнения**, с привязкой к конкретному окружению.

## TC-AE-301 — Переход в выбранный каталог

- **Приоритет:** Medium
- **Тип / техника:** Positive / navigation
- **Requirement:** `REQ-AE-006`
- **Checklist:** `CL-CT-001`–`CL-CT-004`
- **Предусловия:** Доступна главная страница и видна категория с товарами.
- **Тестовые данные:** Фактически доступный пункт меню, например Men → Clothing; записать название и URL.

| № | Действие | Ожидаемый результат (проверяемая гипотеза) |
|---|---|---|
| 1 | Открыть меню категорий | Пользователь видит доступные категории. |
| 2 | Выбрать исследуемую категорию | Открыт соответствующий раздел каталога. |
| 3 | Сопоставить заголовок и содержимое с выбранным пунктом | Содержимое соответствует выбранной категории на уровне доступных признаков. |
| 4 | Открыть одну карточку из каталога | Открыта PDP выбранного товара. |

- **Критерий оценки:** Навигация ведёт к выбранной категории и позволяет открыть товар.
- **Actual Result:** —
- **Status:** `Not Run`
- **Execution ID / Evidence:** —

## TC-AE-302 — Активация Price: Low to High

- **Приоритет:** High
- **Тип / техника:** Positive / state transition
- **Requirement:** `REQ-AE-007`, `REQ-AE-010`
- **Checklist:** `CL-CT-005`–`CL-CT-007`
- **Предусловия:** Открыт каталог, где предусмотрена сортировка `Price: Low to High`.
- **Тестовые данные:** Название/URL категории; исходная сортировка.

| № | Действие | Ожидаемый результат (проверяемая гипотеза) |
|---|---|---|
| 1 | Найти и открыть управление сортировкой | Видны доступные варианты. |
| 2 | Выбрать `Price: Low to High` | Интерфейс принимает выбор. |
| 3 | Проверить отображаемую выбранную опцию | Сортировка отображается как активная или присутствует иной ясный индикатор. |

- **Критерий оценки:** Факт применения опции подтверждён UI. Если отсутствует — зафиксировать `Not Applicable` с названием категории.
- **Actual Result:** —
- **Status:** `Not Run`

## TC-AE-303 — Порядок отображаемых цен после сортировки

- **Приоритет:** High
- **Тип / техника:** Positive / ordering / data comparison
- **Requirement:** `REQ-AE-008`
- **Checklist:** `CL-CT-008`, `CL-CT-009`
- **Предусловия:** Каталог содержит хотя бы 5 товаров и доступную сортировку по возрастанию цены.
- **Тестовые данные:** Список первых 5–10 карточек: название, regular/sale/current price, валюта, отметки «from».

| № | Действие | Ожидаемый результат (проверяемая гипотеза) |
|---|---|---|
| 1 | Активировать сортировку `Price: Low to High` | Опция применена согласно UI. |
| 2 | Зафиксировать 5–10 последовательных карточек в одном состоянии выдачи | Получен набор видимых цен и пометок акций. |
| 3 | Для карточек с однозначной текущей ценой проверить неубывание | Сравнение выполнено на сопоставимых значениях. |
| 4 | Пометить карточки со скидками, ценовым диапазоном или неясной ценой | Неоднозначные элементы выделены, сделан вывод о необходимости уточнить правило. |

- **Критерий оценки:** Если правило сортировки по сравниваемой цене подтверждено, оценить соответствие; иначе `Needs Clarification`.
- **Уточнение:** Вопрос `Q-AE-02`: какую цену реально использует сортировка.
- **Actual Result:** —
- **Status:** `Not Run`
- **Execution ID / Evidence:** —

## TC-AE-304 — Применение ценового фильтра

- **Приоритет:** High
- **Тип / техника:** Positive / equivalence partitioning
- **Requirement:** `REQ-AE-009`, `REQ-AE-010`
- **Checklist:** `CL-CT-011`–`CL-CT-015`
- **Предусловия:** Есть доступный ценовой фильтр и товары в выбранной категории.
- **Тестовые данные:** Опция `$25–$50`, **если действительно присутствует**; иначе фактический диапазон.

| № | Действие | Ожидаемый результат (проверяемая гипотеза) |
|---|---|---|
| 1 | Открыть панель фильтров | Видны доступные ценовые диапазоны. |
| 2 | Выбрать допустимый диапазон и применить | В UI отображается выбранный фильтр. |
| 3 | Зафиксировать список и цены нескольких товаров | Получено наблюдение о составе выдачи. |
| 4 | Сверить цены и пометки скидок с заявленным диапазоном | Неоднозначности регулярной/текущей цены и границ выделены отдельно. |

- **Критерий оценки:** Оценивать отбор товаров как Pass/Fail только при установленном правиле цены и границ; иначе `Needs Clarification`.
- **Уточнение:** Вопросы `Q-AE-02`, `Q-AE-03`.
- **Actual Result:** —
- **Status:** `Not Run`
- **Execution ID / Evidence:** —

## TC-AE-305 — Совместное применение фильтра и сортировки

- **Приоритет:** High
- **Тип / техника:** Combination / state transition
- **Requirement:** `REQ-AE-009`, `REQ-AE-010`
- **Checklist:** `CL-CT-018`–`CL-CT-020`
- **Предусловия:** В одной категории доступны сортировка и ценовой фильтр.
- **Тестовые данные:** Фактический диапазон и `Price: Low to High`.

| № | Действие | Ожидаемый результат (проверяемая гипотеза) |
|---|---|---|
| 1 | Применить ценовой фильтр | Выбранное состояние отражено в UI. |
| 2 | Выбрать сортировку по возрастанию цены | В UI одновременно видны или иначе подтверждаются обе настройки. |
| 3 | Зафиксировать 5–10 карточек и их цены | Выдачу можно проверить на сопоставимость с настройками. |
| 4 | Снять фильтр штатным способом | Интерфейс отражает снятие фильтра; поведение сортировки записано. |

- **Критерий оценки:** Не выдавать сомнительный порядок или изменение цены за продуктовый дефект без бизнес-правила.
- **Уточнение:** Сохранение сортировки после снятия фильтра — `Q-CT-01` / exploratory.
- **Actual Result:** —
- **Status:** `Not Run`
- **Execution ID / Evidence:** —
