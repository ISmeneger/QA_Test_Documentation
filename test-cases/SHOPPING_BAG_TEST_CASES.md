## Перед выполнением

- Использовать только собственную гостевую сессию; при необходимости — отдельный профиль браузера. Не трогать чужие позиции и не оформлять покупку.
- Записать дату/время и часовой пояс, ОС, браузер/версию, URL, регион/локаль, VPN, сессию, наличие pop-up.
- Выбрать в актуальном каталоге два **разных** доступных товара `A` и `B`. Зафиксировать название, ссылку, вариант/размер, цену и SKU (если показан). Не полагаться на постоянное наличие конкретного SKU.
- Между независимыми кейсами восстановить необходимое состояние **только своей** корзины. Если окружение мешает работе (например, anti-bot), указать `Blocked`; не обходить защиту.
- Все предположения в Expected Result подлежат сопоставлению с наблюдаемыми подсказками интерфейса и документацией. Там, где продуктовая логика неизвестна, итог может быть `Needs Clarification`.

## TC-AE-101 — Добавление доступного товара в пустую корзину

- **Приоритет:** Critical
- **Тип:** Positive / Functional / E2E
- **Связи:** `REQ-AE-015`, `CL-BAG-003`, `CL-BAG-005`
- **Предусловия:** сайт доступен; собственная гостевая корзина пуста; товар `A` и нужный вариант доступны для добавления.
- **Данные:** URL/название товара `A`, размер/цвет (если требуется), текущая цена.

| № | Шаг | Ожидаемый результат (проверяемая гипотеза) |
|---|---|---|
| 1 | Открыть страницу товара `A` | Открыта страница выбранного товара |
| 2 | Выбрать доступный обязательный вариант (размер/цвет) | Интерфейс отображает сделанный выбор |
| 3 | Нажать `Add to Bag` один раз | UI подтверждает действие либо обновляет индикатор корзины согласно текущему интерфейсу |
| 4 | Открыть Shopping Bag | В корзине присутствует позиция `A`, её название соответствует выбранному товару |

- **Критерий оценки:** наличие корректной позиции `A` в корзине при подтверждённом доступном варианте.
- **Фактический результат:** —
- **Статус:** `Not Run`
- **Evidence / Run ID:** —

## TC-AE-102 — Сохранение размера/варианта при добавлении

- **Приоритет:** High
- **Тип:** Positive / Data consistency
- **Связи:** `REQ-AE-016`, `CL-BAG-006`, `CL-BAG-007`
- **Предусловия:** товар `A` имеет несколько доступных размеров или вариантов; корзина не содержит `A` либо исходное состояние документировано.
- **Данные:** товар `A`, выбранный размер `S_A`, цвет `C_A` (если применимо); цена на PDP.

| № | Шаг | Ожидаемый результат (проверяемая гипотеза) |
|---|---|---|
| 1 | Открыть PDP товара `A` | Отображаются доступные варианты |
| 2 | Выбрать `S_A` и, при необходимости, `C_A`; записать цену | Выбранные параметры визуально обозначены |
| 3 | Добавить товар в корзину | Появляется позиция выбранного товара |
| 4 | Открыть корзину и сопоставить название, размер/цвет с PDP | Название и выбранные обязательные варианты совпадают |
| 5 | Зафиксировать цену в корзине и сравнить с PDP | Совпадение оценивается с учётом указанных скидок/акций; при непонятном правиле цены — `Needs Clarification` |

- **Критерий оценки:** выбранный обязательный вариант не подменён; ценовые различия анализируются отдельно.
- **Фактический результат:** —
- **Статус:** `Not Run`
- **Evidence / Run ID:** —

## TC-AE-103 — Увеличение quantity на один доступный шаг

- **Приоритет:** Critical
- **Тип:** Positive / State transition
- **Связи:** `REQ-AE-017`, `CL-BAG-009`, `CL-BAG-011`
- **Предусловия:** в собственной корзине ровно одна позиция `A`, quantity = `1`; у товара разрешено количество `2` (по UI/наличию).
- **Данные:** `A`, quantity `1 → 2`.

| № | Шаг | Ожидаемый результат (проверяемая гипотеза) |
|---|---|---|
| 1 | Открыть Shopping Bag | Позиция `A` отображает quantity `1` |
| 2 | Выбрать количество `2` штатным элементом интерфейса | Изменение доступно и принято интерфейсом |
| 3 | Дождаться штатного обновления корзины | Quantity позиции `A` = `2`; название и вариант не изменились |
| 4 | Зафиксировать обновлённую стоимость позиции | Стоимость позиции отражает новое количество по отображаемым правилам |

- **Критерий оценки:** количество обновляется без нежелательной смены товара или варианта.
- **Фактический результат:** —
- **Статус:** `Not Run`
- **Evidence / Run ID:** —

## TC-AE-104 — Subtotal после увеличения количества

- **Приоритет:** Critical
- **Тип:** Functional / Calculation
- **Связи:** `REQ-AE-018`, `CL-BAG-012`, `Q-AE-05`
- **Предусловия:** своя корзина содержит только один товар `A`; доступны quantity `1` и `2`. Если возможно, выбрать товар без дополнительных скидок, иначе все скидки зафиксировать.
- **Данные:** текущая отображаемая цена за единицу `P`, валюта, quantity, отображаемые скидки.

| № | Шаг | Ожидаемый результат (проверяемая гипотеза) |
|---|---|---|
| 1 | Открыть корзину с `A × 1` и записать цену, скидки, subtotal | Значения зафиксированы до изменения |
| 2 | Изменить quantity с `1` на `2` | UI отображает quantity `2` |
| 3 | Записать line total и subtotal после обновления | Значения обновлены без арифметической несогласованности по явным правилам UI |
| 4 | Для случая **без скидок** сопоставить с `P × 2`; при скидках отдельно записать корректировки | Для простой модели subtotal = `P × 2`; при акциях ожидаемое правило уточняется (`Needs Clarification`, если оно неизвестно) |

- **Критерий оценки:** расчёт сверяется только с подтверждённой моделью ценообразования; taxes, shipping и итог заказа не приравниваются автоматически к subtotal.
- **Фактический результат:** —
- **Статус:** `Not Run`
- **Evidence / Run ID:** —

## TC-AE-105 — Добавление двух разных товаров

- **Приоритет:** High
- **Тип:** Positive / E2E / Data consistency
- **Связи:** `REQ-AE-020`, `CL-BAG-015`, `CL-BAG-016`, `CL-BAG-017`
- **Предусловия:** собственная корзина пуста; `A` и `B` — разные доступные товары/SKU.
- **Данные:** `A` и `B`, по одному доступному варианту каждого, quantity `1`.

| № | Шаг | Ожидаемый результат (проверяемая гипотеза) |
|---|---|---|
| 1 | Выбрать вариант товара `A` и добавить в корзину | В корзине появилась позиция `A` |

| 3 | Открыть Shopping Bag | Видны две различимые позиции `A` и `B` |
| 4 | Сверить названия, размеры и quantity по каждой позиции | Данные соответствуют выбранным товарам; quantity = `1` для каждого, если пользователь не менял его |
| 5 | Зафиксировать цены строк, скидки и subtotal | Значения можно сопоставить с отображаемыми правилами расчёта; при неясности — `Needs Clarification` |

- **Критерий оценки:** разные товары представлены различимыми позициями без потери выбранных вариантов.
- **Фактический результат:** —
- **Статус:** `Not Run`
- **Evidence / Run ID:** —

- **Связи:** `REQ-AE-019`, `REQ-AE-020`, `CL-BAG-018`, `CL-BAG-019`, `CL-BAG-020`
- **Предусловия:** в собственной корзине две разные позиции `A` и `B` (по `1` шт.); названия/варианты зафиксированы.
- **Данные:** удалить только `A`.

| № | Шаг | Ожидаемый результат (проверяемая гипотеза) |
