> Независимый учебный проект, не связанный с American Eagle. `REQ-AE-XXX` — проверяемые гипотезы, а не утверждённые требования компании. Все четыре тест-кейса имеют статус `Not Run`; фактические результаты отсутствуют. Неясное ожидаемое поведение требует уточнения и само по себе не доказывает дефект.

## Правила подготовки и выполнения

- Для каждого прогона записать дату, время, часовой пояс, ОС, браузер/версию, регион, локаль, наличие VPN, тип сессии и URL.
- Использовать только открытый интерфейс сайта, без обхода anti-bot, реального оформления заказов или массовых действий.
- Выбрать актуальный товар `A`, доступный для просмотра, с размером/вариантом, если применимо. Записать название, URL, выбранный размер/цвет, показанную цену и SKU (если он доступен в UI).
- Для сценария недоступного варианта выбрать подходящий товар только при его естественном наличии в интерфейсе. Не имитировать отсутствие остатков.
- Исходное состояние **своей** гостевой корзины задокументировать до добавления товара. Не очищать чужую корзину и не публиковать персональные данные или токены.
- В случае защитной блокировки использовать `Blocked`. Если предположение о бизнес-правиле нельзя подтвердить, использовать `Needs Clarification`, а не объявлять продуктовый дефект.

## TC-AE-401 — Открытие карточки товара и отображение основных данных

- **Приоритет:** High
- **Тип:** Positive / UI / Data consistency
- **Requirement:** `REQ-AE-011`, `REQ-AE-012`
- **Checklist:** `CL-PD-001`–`009`
- **Предусловия:** сайт доступен; в открытой категории имеется карточка товара `A`.
- **Тестовые данные:** название и URL категории; выбранный товар `A`.

| № | Шаг | Ожидаемый результат — проверяемая гипотеза |
|---|---|---|
| 1 | Открыть доступную категорию товаров | Отображается каталог с карточками товаров |
| 2 | Зафиксировать название и цену товара `A` в каталоге | Название и показанная цена записаны для сравнения |
| 3 | Нажать на карточку `A` | Открывается страница выбранного товара (PDP) |
| 4 | Сопоставить название на PDP с выбранной карточкой | Отображается тот же товар, без необъяснимой подмены |
| 5 | Проверить на PDP название, текущую цену и главное изображение | Основные данные доступны для просмотра; варианты цены со скидкой записаны отдельно |
| 6 | Зафиксировать доступные параметры (размер/цвет), если они есть | Видимые варианты и их состояния задокументированы |

- **Критерий оценки:** согласованность выбранного товара и его основных данных. Промоакции, региональная цена и варианты могут потребовать уточнения.
- **Фактический результат:** —
- **Статус:** `Not Run`
- **Execution ID / Evidence:** —

## TC-AE-402 — Выбор размера и переключение доступных вариантов

- **Приоритет:** High
- **Тип:** Positive / State transition
- **Requirement:** `REQ-AE-013`
- **Checklist:** `CL-PD-010`–`013`
- **Предусловия:** PDP товара `A` открыта; в интерфейсе доступно как минимум два выбираемых размера. Если таких размеров нет — `Not Applicable` с пояснением.
- **Тестовые данные:** доступные размеры `S1` и `S2`, цвет (если применимо).

| № | Шаг | Ожидаемый результат — проверяемая гипотеза |
|---|---|---|
| 1 | Записать текущее состояние выбора размера | Зафиксирован исходный вариант или отсутствие выбора |
| 2 | Выбрать доступный размер `S1` | UI явно отражает выбранный `S1` |
| 3 | Выбрать другой доступный размер `S2` | UI явно отражает `S2` как актуальный выбор |
| 4 | Проверить, сохранилось ли отображение ранее выбранного размера | Не возникает неоднозначности, какой размер активен |
| 5 | Если доступен выбор цвета, переключить цвет и записать размер | Изменение размера/цвета наблюдаемо; возможный сброс выбора задокументирован для уточнения правил |

- **Критерий оценки:** пользователь может определить текущий выбранный вариант. Поведение при смене цвета оценивается с учётом доступности вариантов.
- **Фактический результат:** —
- **Статус:** `Not Run`
- **Execution ID / Evidence:** —

## TC-AE-403 — Состояние Add to Bag при выбранном и невыбранном варианте

- **Приоритет:** High
- **Тип:** Negative + Positive / Decision table
- **Requirement:** `REQ-AE-014`
- **Checklist:** `CL-PD-014`–`017`
- **Предусловия:** открыта PDP товара, для которого есть обязательный выбор размера; доступен хотя бы один размер. Наличие sold-out размера необязательно.
- **Тестовые данные:** товар `A`, доступный `S1`, при наличии — недоступный `S0`.

| № | Шаг | Ожидаемый результат — проверяемая гипотеза |
|---|---|---|
| 1 | Открыть PDP и зафиксировать, выбран ли размер по умолчанию | Исходный выбор и состояние кнопки `Add to Bag` записаны |
| 2 | Если размер не выбран, проверить состояние и штатное действие `Add to Bag` | Интерфейсное правило (запрет добавления, подсказка или автоматический выбор) зафиксировано; допустимый вариант требует уточнения |
| 3 | Выбрать доступный размер `S1` | Выбор визуально отмечен; текущее состояние CTA зафиксировано |
| 4 | Проверить, позволяет ли UI добавить доступный вариант | Поведение согласуется с текущими подсказками UI; неожиданные ограничения описаны отдельно |
| 5 | Если естественно представлен недоступный `S0`, проверить его визуальное состояние без добавления | Состояние sold-out варианта и CTA зафиксировано, без попытки искусственно менять остатки |

- **Критерий оценки:** описаны доступные комбинации `выбор размера × доступность SKU × Add to Bag`. Если бизнес-правило неизвестно, итог может быть `Needs Clarification`.
- **Фактический результат:** —
- **Статус:** `Not Run`
- **Execution ID / Evidence:** —

## TC-AE-404 — Сопоставление товара на PDP и в Shopping Bag

- **Приоритет:** Critical
- **Тип:** Positive / E2E / Data consistency
- **Requirement:** `REQ-AE-015`, `REQ-AE-016`
- **Checklist:** `CL-PD-018`–`022`
- **Предусловия:** собственная гостевая корзина имеет известное состояние; товар `A` доступен для добавления; выбран обязательный размер/цвет, если применимо.
- **Тестовые данные:** название и URL товара `A`, размер `S1`, цвет, цена/валюта на PDP, SKU (если доступен).

| № | Шаг | Ожидаемый результат — проверяемая гипотеза |
|---|---|---|
| 1 | На PDP записать название, выбранный размер/цвет и текущую цену | Исходные данные зафиксированы |
| 2 | Нажать `Add to Bag` один раз | Интерфейс отображает подтверждение либо изменение состояния корзины |
| 3 | Открыть Shopping Bag | Добавленный товар `A` представлен различимой позицией |
| 4 | Сравнить название и выбранные варианты с записанными на PDP | Название и обязательные варианты соответствуют выбору пользователя |
| 5 | Сопоставить цену на PDP и в Shopping Bag, записать применённые промоусловия | Цена и валюта сопоставлены; неясные отличия помечены `Needs Clarification`, а не сразу `Failed` |

- **Критерий оценки:** товар и выбранный вариант сохраняются без необъяснимой подмены; правила динамического ценообразования уточняются отдельно.
- **Фактический результат:** —
- **Статус:** `Not Run`
- **Execution ID / Evidence:** —
