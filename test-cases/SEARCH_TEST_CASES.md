## Общие правила выполнения

- Перед прогоном зафиксировать дату/время и часовой пояс, ОС, браузер/версию, регион и локаль, VPN, URL, тип сессии и всплывающие окна.
- Использовать только публичный UI и обычные действия пользователя. Не обходить anti-bot, не выполнять массовые запросы и не публиковать cookies или токены.
- Для тестов подбирать доступные на момент запуска товары/категории. Если входное условие не выполняется, фиксировать `Blocked`/`Not Applicable` с пояснением, а не выдумывать результат.
- `Actual Result`, `Execution ID` и `Evidence` заполнять **только после выполнения**, с привязкой к конкретному окружению.

## TC-AE-201 — Открытие поля поиска и ввод текста

- **Приоритет:** High
- **Тип / техника:** Positive / UI
- **Requirement:** `REQ-AE-001`
- **Checklist:** `CL-SR-001`–`CL-SR-003`
- **Предусловия:** Открыта главная страница US storefront; поисковый элемент доступен.
- **Тестовые данные:** Нейтральный текст запроса: `jeans`.

| № | Действие | Ожидаемый результат (проверяемая гипотеза) |
|---|---|---|
| 1 | Найти элемент поиска в шапке | Видим доступный пользователю элемент поиска. |
| 2 | Активировать поиск штатным способом | Появляется доступное поле ввода. |
| 3 | Ввести `jeans` | В поле отображается введённая строка без нежелательных изменений. |

- **Критерий оценки:** Поле доступно и принимает ввод. При блокировке окружением — `Blocked`.
- **Actual Result:** —
- **Status:** `Not Run`
- **Execution ID / Evidence:** —

## TC-AE-202 — Поиск актуального существующего товара

- **Приоритет:** High
- **Тип / техника:** Positive / E2E / equivalence partitioning
- **Requirement:** `REQ-AE-002`, `REQ-AE-003`
- **Checklist:** `CL-SR-004`–`CL-SR-008`
- **Предусловия:** В актуальном каталоге выбран доступный товар с известным названием.
- **Тестовые данные:** Записать фактическое название товара `P`, запрос `Q` (ключевые слова названия), URL товара.

| № | Действие | Ожидаемый результат (проверяемая гипотеза) |
|---|---|---|
| 1 | Открыть поиск и ввести `Q` | Строка введена. |
| 2 | Отправить запрос через Enter или штатную кнопку | Появляется область/страница результатов. |
| 3 | Найти карточку, релевантную `Q` | Есть как минимум один результат, связанный с искомым товаром по выбранным словам — как проверяемая гипотеза. |
| 4 | Открыть найденный результат | Открыта карточка выбранного товара, название сопоставимо с результатом поиска. |

- **Критерий оценки:** Зафиксировать запрос и точную карточку, по которой сделан вывод о релевантности.
- **Уточнение:** Алгоритм релевантности не документирован; отсутствие ожидаемого товара сначала анализировать, не объявлять подтверждённым багом.
- **Actual Result:** —
- **Status:** `Not Run`
- **Execution ID / Evidence:** —

## TC-AE-203 — Повторный запрос после изменения текста

- **Приоритет:** Medium
- **Тип / техника:** State transition / functional
- **Requirement:** `REQ-AE-003`
- **Checklist:** `CL-SR-009`
- **Предусловия:** Поиск доступен; есть два безопасных запроса для реально существующих типов товаров.
- **Тестовые данные:** `Q1=jeans`, `Q2=shirt` — примеры; записать фактически использованные запросы.

| № | Действие | Ожидаемый результат (проверяемая гипотеза) |
|---|---|---|
| 1 | Выполнить поиск `Q1` | Открыта выдача для `Q1`. |
| 2 | Повторно активировать поиск и заменить ввод на `Q2` | В поле отображается `Q2`. |
| 3 | Отправить `Q2` | Видима обновлённая выдача или иное явно наблюдаемое состояние поиска. |
| 4 | Зафиксировать URL, строку запроса и несколько результатов | Можно установить, к какому запросу относится видимая выдача. |

- **Критерий оценки:** После нового запроса интерфейс не показывает предыдущий запрос как текущий; фиксировать наблюдаемое состояние.
- **Actual Result:** —
- **Status:** `Not Run`
- **Execution ID / Evidence:** —

## TC-AE-204 — Обработка бессмысленного запроса

- **Приоритет:** High
- **Тип / техника:** Negative / exploratory / equivalence partitioning
- **Requirement:** `REQ-AE-004`
- **Checklist:** `CL-SR-012`, `CL-SR-013`
- **Предусловия:** Поиск доступен в обычной гостевой сессии.
- **Тестовые данные:** Уникальный бессмысленный запрос из букв, например `zzqvnotarealitemx`; записать точную строку.

| № | Действие | Ожидаемый результат (проверяемая гипотеза) |
|---|---|---|
| 1 | Ввести бессмысленный запрос | Текст принят полем. |
| 2 | Отправить запрос | Интерфейс завершает обработку запроса или показывает явное состояние ошибки/блокировки. |
| 3 | Записать видимые заголовки, сообщения, список результатов и рекомендации | Получено фактическое описание UI, без предположения о должном no-results. |
| 4 | Если есть выдача, отдельно определить признаки рекомендаций и точных совпадений | Зафиксировано, есть ли визуальные различия между типами выдачи. |

- **Критерий оценки:** Цель — наблюдение с доказательствами. При отсутствии подтверждённого правила используем `Needs Clarification`, а не `Failed` только из-за наличия товаров.
- **Уточнение:** Связанный открытый вопрос: `Q-AE-01`.
- **Actual Result:** —
- **Status:** `Not Run`
- **Execution ID / Evidence:** —

## TC-AE-205 — Обработка пустого поискового запроса

- **Приоритет:** Medium
- **Тип / техника:** Negative / exploratory
- **Requirement:** `REQ-AE-005`
- **Checklist:** `CL-SR-010`, `CL-SR-011`
- **Предусловия:** Поиск доступен; поле можно очистить.
- **Тестовые данные:** Пустая строка `""`.

| № | Действие | Ожидаемый результат (проверяемая гипотеза) |
|---|---|---|
| 1 | Открыть поиск и убедиться, что поле пустое | Поле не содержит символов. |
| 2 | Попробовать штатную отправку пустого запроса (если доступна) | Поведение интерфейса зафиксировано: блокировка отправки, подсказка, рекомендации либо переход. |
| 3 | Зафиксировать тексты, URL и состояние элементов | Есть воспроизводимое описание реакции интерфейса. |

- **Критерий оценки:** Без подтверждённых правил пустого ввода — `Needs Clarification` при исследованном поведении, не фиктивный Pass.
- **Уточнение:** Вопрос `Q-SR-03` о правилах пустой строки.
- **Actual Result:** —
- **Status:** `Not Run`
- **Execution ID / Evidence:** —
