## 1. Цель и границы

Проверить навигацию в каталог, отображение товаров, работу доступных пользователю сортировок и фильтра по цене, а также корректность отображения выбранных параметров. Основной приоритет — сценарии, которые помогают пользователю найти и выбрать товар.

**Включено:** доступная категория Men's Clothes или другая актуальная категория; сортировка `Price: Low to High`, *если она есть в интерфейсе*; ценовой диапазон `$25–$50`, *если он доступен*; обновление выдачи и переход в карточку товара.

**Исключено:** массовая загрузка каталога, нагрузочные тесты, обход защит сайта, оформление покупок, администрирование ассортимента и подтверждение внутренней логики ценообразования без спецификации.

## 2. Подготовка к ручному выполнению

- [ ] Записать дату/время с часовым поясом, URL, ОС и версию браузера.
- [ ] Указать регион, локаль, наличие VPN, guest/auth-сессию и состояние cookies.
- [ ] Выбрать фактически доступную категорию с несколькими товарами; записать её название и URL.
- [ ] Проверить, присутствуют ли сортировка по цене и ценовой фильтр: при отсутствии поставить `Not Applicable` для соответствующих пунктов, а не `Failed`.
- [ ] Зафиксировать показанные цены для 5–10 последовательных карточек *в одном состоянии выдачи*; учитывать возможные sale/regular цены и вариации.
- [ ] При всплывающих окнах пользоваться только штатным закрытием; если anti-bot блокирует выполнение — `Blocked`.
- [ ] Не публиковать персональные данные, cookies, access token или иные секреты.

## 4. Техники тест-дизайна и данные

| Подход | Что сравниваем | Ограничение |
|---|---|---|
| Классы эквивалентности | Категория с ассортиментом / без доступных результатов; товар с обычной / скидочной ценой | Сначала зафиксировать реальные доступные состояния |
| Проверка сортировки | Последовательность видимых цен после `Price: Low to High` | Не делать вывод о дефекте, пока не установлено, какая цена участвует в сортировке |
| BVA | Товар на нижней и верхней границе ценового диапазона | Не считать границы включёнными без подтверждения правила |
| Переходы состояний | Без фильтра → фильтр → сортировка → снятие фильтра | Фиксировать изменение UI и перечня карточек |
| Pairwise / комбинации | Сортировка + диапазон + sale/regular | Не нужно механически перебирать все комбинации |

Пример протокола для сортировки: сохраните `URL`, название категории, выбранную сортировку, последовательность `Название — отображаемая цена — пометка sale/regular` для 5–10 карточек и снимок экрана. При карточке с диапазоном цен, несколькими SKU или неоднозначной ценой обозначьте её `Ambiguous` и не используйте для окончательного вывода о порядке до уточнения.
