Условия расчёта subtotal, скидок, лимитов quantity и правила объединения SKU требуют подтверждения.

## 1. Цель и границы

Проверить основной покупательский поток на уровне корзины: `Product Details → Add to Bag → Bag → Quantity Update → Remove Item`, согласованность данных между PDP и корзиной, несколько товаров и арифметику отображаемых сумм.

**In scope:** гостевая корзина, товары из открытого каталога, изменение количества, удаление, размер/вариант/SKU (если доступны пользователю), отображаемые цены, скидки, subtotal, пустое состояние.

**Out of scope:** оформление и оплата реальных заказов, попытки обхода anti-bot, нагрузочное тестирование, вмешательство в чужие сессии, необъявленные внутренние API-контракты.

## 2. Предусловия и тестовые данные

- [ ] Записать фактические дату, время и часовой пояс; ОС, браузер/версию, локаль/регион, VPN и тип сессии.
- [ ] Проверить доступность сайта в обычном браузерном сценарии; при защитной блокировке использовать `Blocked`, без обхода.
- [ ] Создать/использовать собственную гостевую сессию и записать исходное состояние корзины; не удалять незнакомые позиции.
- [ ] Выбрать актуальный товар A с доступным размером/вариантом; записать название, URL, выбранный размер, SKU/ID (если отображается), цену и валюту.
- [ ] По возможности выбрать отличный от него товар B; зафиксировать соответствующие данные.
- [ ] Для расчётных проверок фиксировать отображаемые цены, количество, скидки, применённые промоакции, налоги и доставку как отдельные строки, если они присутствуют.
- [ ] Перед каждым независимым сценарием явно определить стартовое состояние; не считать корзину пустой по умолчанию.

## 4. Модель переходов состояний

| Начальное состояние | Действие | Исследуемое конечное состояние | Связь |
|---|---|---|---|
| Empty | Add A | One item: A | `REQ-AE-015` |
| One item: A | Increase quantity | One item: A, updated quantity | `REQ-AE-017` |
| One item: A | Add B | Two distinct items: A + B | `REQ-AE-020` |
| Two items: A + B | Remove A | One item: B | `REQ-AE-019` |
| One item: B | Remove B | Empty | `REQ-AE-019` |

Переходы — **модель для тест-дизайна**, а не уже подтверждённая реализация. Следует записывать фактическое состояние после каждого действия.

## 5. Проверка расчётов

Для корзины без скидок, с однозначной ценой за единицу, исследуется гипотеза:

`line_total = displayed_unit_price × quantity`

`subtotal = sum(line_totals)`

**Это не универсальное утверждение о сайте:** скидки на наборы, промоакции, округление, различия между отображаемой и расчётной ценой могут изменять результат. Налоги, доставка и итог заказа не приравниваются автоматически к subtotal.

Для воспроизводимой проверки записать исходные цены и суммы с валютой, отдельные скидки, количество, время и URL товара. Если фактические правила неизвестны — `Needs Clarification`, а не `Confirmed Bug`.
